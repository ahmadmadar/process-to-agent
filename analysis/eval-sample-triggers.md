# Eval Sample: Trigger Table

> Fictional engagement for portfolio purposes. The client, stakeholders and data are synthetic.

Generated by `analysis/eval_sample_triggers.py` from `data/released/eval_sample.csv`
(release 2) and `claims_r2_fields.csv`. It shows which decision-tree inputs each
claim carries. **It does not compute a route or a decision**; expected outcomes are
the consultant's. The historical outcome is shown for reference only: it is what
happened under the current process, not the expected outcome under the redesign.

Thresholds: $10k (provisional; D3); deductible assumed $25,000 (D1); both on the claimed
amount (G4). `FALLBACK_DEADLINE_DAYS` = 14 (P2).

## Not derivable from the released data

These checks have no field in the eval sample. A claim can only test them if
the consultant adds the input to the eval case (for example, a synthetic
expedite request or temperature allegation in the claim text).

| Check | Tree step / row | Why not derivable |
|---|---|---|
| Temperature-excursion allegation | Step 1 / R1 (G5) | No allegation field; only `reefer_flag` and `temp_log_obtained` |
| Cold-chain contract customer | Step 1 / R2 | Customers are named in T2:L44, but the release has `customer_id` only, with no name mapping |
| Account-manager expedite request | Step 1 / R3 | No request field; `decided_by_role` records who decided historically, not a request |
| Invoice mismatch | Step 3 / R8 | `invoice_received` flag only; no invoice amount |
| Outside the customer filing window | Step 3 / R9 | No window length in the data; the historical denial reason is an outcome, not an input |
| Withdrawal | G12 | No withdrawn status in the sample |
| Confidence gates | Step 6 / R14 (G11) | Produced by the agent at run time (P1 unset) |
